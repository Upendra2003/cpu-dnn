Approximate multiplication inside a DNN, bit by bit

Every multiplication in MNIST and Fashion-MNIST networks goes through the RoBA family of approximate multipliers from Rajiv & Kedia (DATE 2026). The networks are trained on a GPU, then run on a simulated multiplierless Ibex RISC-V core that has one added instruction, LOD. They keep their accuracy.

Background

Round to a power of two, then shift

RoBA rounds each operand to a power of two (Ar, Br) and drops the small error term, so a multiply becomes shifts and adds. Finding the leading one is the slow part in software, which is what the LOD instruction fixes.

No multiplier at all: a table of squares

Σk xkwk = ( Σk S[xk + wk] − Σk S[xk] − Σk S[wk] ) / 2
S[v] = v², a 509-entry table for v = −254…254 (1 KB)

The polarization identity turns every product into one lookup in a table of squares. Σ S[x] is computed once per layer input and shared by all output neurons, and Σ S[w] is fixed per neuron, so each multiply-accumulate costs a single table load. The products are exact, and no LOD instruction is needed.

It works this well because Ibex reads its RAM in one cycle and int8 + int8 indexes a small table. At int16 the table would need 131,071 entries (512 KB), while the LOD-based RoBA routines cost the same at any width.

Skipping zeros

Model Exact, fusedRoBA-Dn1, fusedSquare table

Skip zeros: fully connected layers gather the nonzero activations once per layer input and loop only over those; conv layers skip taps whose input is zero. The multiplier versions already skip zero operands one product at a time; the square table otherwise visits every product.

Raw pixels: the input normalization (x − mean) / std is folded into the first layer's weights and bias, so the network reads raw pixels, and the background is exactly zero (81% of MNIST and 51% of Fashion-MNIST test pixels). For LeNet-5 the fold gives conv1 one bias per output position, because zero padding of raw pixels is not zero padding of normalized ones.

ROBA_ITERATIONS = {
    "roba_dn1":    [round_dn],
    "roba_updn":   [round_updn],
    "roba_dn2":    [round_dn, round_dn],
    "roba_updndn": [round_updn, round_dn],
    "roba_updn2":  [round_updn, round_updn],
}

def factors(x, mult, side, integer=True):
    out, r = [], x
    for rnd in ROBA_ITERATIONS[mult]:
        rr = _signed_round(r, rnd)
        # Ar*b + (a - Ar)*Br
        out += [rr, r - rr] if side == "a" else [r, rr]
        r = r - rr
    return out

    Limits · next

    Read with care, then measure

    Limits
    • One seed per dataset. Accuracy differences under about 0.1 points are noise.
    • Ibex cycles are measured in simulation on the first 100 test images per configuration; energy multiplies them by the paper's relative core power, not a power measurement.
    • Our Mitchell is the classic algorithm. The paper's Mitchell gives the same products as RoBA-Dn1.
    • int16 sums exceed 32 bits, so int16 on Ibex needs 64-bit accumulation that the estimate leaves out.
    • The square table relies on one-cycle RAM and a 1 KB table. With caches, wait states or int16 operands (a 512 KB table) the balance against LOD-based RoBA changes.
    Next
    1. 3–5 seeds per dataset, mean ± standard deviation.
    2. CIFAR-10 with a small CNN.
    3. Per-layer choice of multiplier: cheap where tolerant, accurate where sensitive.
    4. int16 networks on Ibex, where a table of squares no longer fits and RoBA keeps its cost.
    5. FPGA: the same Ibex + LOD RTL on a board, measuring cycles and power on silicon.

    Source paper: S. P. Rajiv and R. Kedia, “Software-Based Approximate Multiplication on Multiplierless CPUs Using Custom Instruction,” DATE 2026.
