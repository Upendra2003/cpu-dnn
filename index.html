Approximate multiplication inside a DNN, bit by bit

Every multiplication in an MNIST network goes through the RoBA family of approximate multipliers from Rajiv & Kedia (DATE 2026), the routines a multiplierless Ibex RISC-V core runs with one custom LOD instruction. The network keeps its accuracy. The open question is how much energy that saves on the core.

Method

How it was run

One library in three implementations that agree bit for bit (PyTorch, Python, C), checked by 27 tests, and one driver script for the whole study.

  1. Characterize the multipliers on 1 million random pairs at 8 and 16 bits.
  2. Train float baselines: 15 epochs, Adam 1e-3 with cosine decay, batch 128, seed 0.
  3. Evaluate in four domains (float, truncated int, int8, int16) × 8 multipliers on the 10,000 test images.
  4. Fine-tune 3 epochs with the approximate forward pass and a straight-through gradient, Adam 1e-4.
  5. Estimate energy from multiplications per inference (MLP 234,752; LeNet-5 416,520) and the paper's cycle and power figures.
RoBA(a, b) = Ar·b + (a − Ar)·Br → every variant is a sum of per-operand products, so an approximate matmul is 1–4 exact matmuls.
# roba/multipliers.py
ROBA_ITERATIONS = {
    "roba_dn1":    [round_dn],
    "roba_updn":   [round_updn],
    "roba_dn2":    [round_dn, round_dn],
    "roba_updndn": [round_updn, round_dn],
    "roba_updn2":  [round_updn, round_updn],
}

def factors(x, mult, side, integer=True):
    out, r = [], x
    for rnd in ROBA_ITERATIONS[mult]:
        rr = _signed_round(r, rnd)
        # Ar*b + (a - Ar)*Br
        out += [rr, r - rr] if side == "a" else [r, rr]
        r = r - rr
    return out
/* csrc/roba.c: RoBA-Dn1 for Ibex */
uint32_t roba_dn1_u(uint32_t a, uint32_t b)
{
    if (a == 0 || b == 0)
        return 0;
    return roba1(a, b, LOD(a), LOD(b));
}

static inline uint32_t roba1(uint32_t a, uint32_t b,
                             uint32_t pa, uint32_t pb)
{
    return (b << pa) + (a << pb)
         - ((1u << pa) << pb);
}

Limits

Read with care

  • One seed. Accuracy differences under about 0.1 points are noise.
  • MNIST is too easy to separate the multipliers; Fashion-MNIST or CIFAR-10 is the next test.
  • Energy covers multiplications only and uses cycle counts read off the paper's figures, for unsigned operands.
  • Our Mitchell is the classic algorithm. The paper's Mitchell gives the same products as RoBA-Dn1.
Source paper: S. P. Rajiv and R. Kedia, “Software-Based Approximate Multiplication on Multiplierless CPUs Using Custom Instruction,” DATE 2026.
